# SpotMicro ESP32 simulation — MuJoCo residual-gait training

MuJoCo physics + Gymnasium + Stable-Baselines3 PPO for training a **residual walking policy**
on the SpotMicro ESP32 quadruped (`SPOTMICRO_ESP32` firmware variant). The baseline is the ESP32 firmware gait ported to NumPy; the
policy learns only small per-foot corrections on top (`residual_pure`, à la spot_mini_mini D2 /
the Hexapod project). A zero action reproduces the firmware gait, so training starts from a
working gait and only learns stabilization.

Managed with **uv** (Python ≥ 3.13).

```bash
uv sync
```

## Architecture

```
command [vx, vy, yaw]  ->  analytic_gait_action  ->  firmware gait (phase clock, trot
                                                     offsets, stance + 12-pt Bezier swing)
   -> Cartesian foot targets (base frame)  + policy residual (12-D, ±30 mm)
   -> firmware legIK  ->  12 joint angles  ->  MuJoCo position actuators (100 Hz control)
```

- `src/robot/firmware_gait.py` — NumPy port of Leika's `esp32/.../walk_state.h` + its firmware `legIK`
  from `esp32/include/kinematics.h` (verified to 0.0 mm against MuJoCo forward kinematics) +
  command→gait map.
- `src/sim/mj_runtime.py` — MuJoCo runtime wrapper (load model, IK→ctrl, IMU/contacts).
- `src/sim/domain_rand.py` — per-episode/step domain randomization for sim-to-real.
- `src/envs/quadruped_mj_env.py` — Gymnasium env; 12-D residual action, 38-D hardware-only
  observation (gravity-in-body, gyro, rpy, prev joint cmd, gait phase, command, prev action),
  ANYmal-style exponential velocity/yaw tracking reward.
- `src/resources/spotmicro_esp32/` — MJCF `scene.xml` / `scene_terrain.xml` (generated by
  `generate_scene.py`), the printed-part and servo meshes placed by `fit_print_meshes.py`
  (`print_parts.json`), tuned `gait_coef.json`.
- `src/leika/` — high-level `Robot` façade (`stand`/`walk`/`rest`) over the sim.

The model is the printed robot: Michael Kubina's SpotMicroESP32
([GitHub](https://github.com/michaelkubina/SpotMicroESP32), GPL-3.0; long knee mounts, SZBK07
electronics plate) with robjk's reinforced shoulders and medium rear cover
([Thingiverse 4937631](https://www.thingiverse.com/thing:4937631), CC BY), and MG996R servos. Each
MuJoCo joint angle equals the firmware's legIK angle; the leg/body dimensions are **measured in
Kubina's assembled model**, and come out close to Leika's `SPOTMICRO_ESP32` `KinConfig`
(`esp32/include/kinematics.h`), which is built on the same design:

| Dimension (mm) | Measured | Firmware |
|---|---|---|
| Body length L (front ↔ rear femur axes) | 205.9 | 207.5 |
| Body width W (left ↔ right hip axes) | 78.0 | 78.0 |
| Coxa (hip axis → leg plane, sideways) | 60.9 | 60.5 |
| Coxa offset (hip axis → femur axis, down) | 10.0 | 10.0 |
| Femur (femur axis → knee axis) | 111.0 | 111.2 |
| Tibia (knee axis → foot-tip arc centre) | 118.0 | 118.5 |
| Foot tip radius (arc centre → ground) | 19.9 | – |

How they were measured: Kubina's FreeCAD assembly holds every part, servo and foot in place. The
joint axes are the servo output gears and shoulder pins, the foot is the arc its tread lies on
(averaged over the four legs). Each print STL was fitted onto its counterpart in the assembly (ICP,
~0.2–0.8 mm RMS), and robjk's parts onto the Kubina parts they replace. robjk's shoulder cover and
extended servo cap keep their pose from robjk's own FreeCAD file, with the cap's arm pointing up.

Masses (~2.13 kg total) = printed parts (~865 g: 20% PLA infill, the hull covers solid as Kubina
prints them) + 12 MG996R (servo meshes from Kubina's assembly) + 2S 2200 mAh LiPo + electronics +
hardware (estimates in `generate_scene.py`). Servo strength is MG996R (~11 kg·cm).

To rebuild after changing parts or the skeleton (constants in `src/robot/firmware_gait.py`):

```bash
uv run --with trimesh python -m src.resources.spotmicro_esp32.fit_print_meshes   # needs the print STLs
uv run python -m src.resources.spotmicro_esp32.generate_scene
```

`fit_print_meshes.py` (~15 min) reads the STLs from `hardware/print` (or a folder passed as an
argument) and the assembled models from `reference/assemblies.zip`. It prints the skeleton it
measures next to the constants. Only the masses, servo settings and colours (in
`generate_scene.py`) need the second command alone. `reference/assemblies.zip` is made by
`extract_assembly.py` from Kubina's `assembly/spotmicroesp32_assembled_quick_and_dirty.FCStd` and
robjk's two `.FCStd` files (see its docstring; needs `cadquery-ocp`).

## Commands

```bash
uv run python -m src.robot.firmware_gait   # IK/FK self-test + stance angles
uv run python replay_gait.py --headless    # validate the zero-residual gait (all directions)
uv run python replay_gait.py --vx 0.1      # watch the baseline gait in the viewer
uv run python teleop.py                    # drive it: arrow keys in the viewer, `help` in the terminal
uv run python teleop.py --stairs 0.005     # ...with a staircase ahead (5 mm steps)

uv run python optimize_gait.py --iters 30  # calibrate command->gait map -> gait_coef.json

uv run python train_mj.py --smoke                                   # pipeline sanity run
uv run python train_mj.py --randomize --zero-final --init-std 0.3 \
    --curriculum --resample-steps 300 --timesteps 5_000_000 --num-envs 16

uv run python eval_policy.py runs/residual_pure_dr --vx 0.1         # watch a trained policy
uv run python visionary_demo.py                                     # high-level API demo

uv run pytest -q                                                    # regression tests
```

Uneven ground: pass `--terrain 0.02` to `train_mj.py` to train on the heightfield scene
(`scene_terrain.xml`) with per-episode random bumps up to the given height in metres. The policy
is blind (IMU only, no exteroception), so terrain only enters through proprioception.

Stairs: pass `--stairs <rise_m>` to `teleop.py`, `replay_gait.py`, `train_mj.py` or `eval_policy.py` to
add a staircase (4 steps up, a landing, 4 down; `src/sim/stairs.py`) starting 0.45 m ahead of the
robot. With MG996R servos the zero-residual firmware gait (20 mm swing) climbs only ~5 mm steps; with
20-35 kg*cm servos and a 40 mm swing it climbs ~20 mm. Higher needs a trained policy.

TensorBoard: `uv run tensorboard --logdir runs`. Watch `terms/r_vel` (tracking) rise and
`terms/p_res` (residual magnitude) stay small — the policy should stabilize, not replace, the gait.
